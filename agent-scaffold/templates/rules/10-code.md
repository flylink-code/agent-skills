# 改代码纪律

## 顺序（不可跳）

1. **定位**：先用 `doc/CODE_MAP_INDEX.md` 的 `--find` / `--outline` / `--map` 拿到 `路径:行号`，再打开文件。禁止全仓大范围 grep 盲扫。
2. **读懂**：改动点上下游各读一层（调用方 + 被调用方）。不确定就写清楚"我不确定 X"。
3. **改**：最小 diff。不改无关格式、不顺手重命名、不动别人的风格。
4. **验**：跑该模块的测试或最小可执行路径；跑不了就说明"没跑"，**不要**写"应该没问题"。
5. **记**：影响面写进提交信息或 `agent/context/decisions.md`。

## 最小 diff 的具体含义

- 一个提交只解决一件事。夹带的重构单独提。
- 不引入新依赖，除非用户同意；不升级锁定版本。
- 生成物（`doc/codemap/**`、`doc/CODE_MAP_INDEX.md`）只由生成器写，**不手改**。
- 改动跨越 3 个以上文件时，先说清为什么要跨。

## 什么时候必须先问

- 要删/改公共 API、数据库结构、对外协议。
- 要动构建配置、CI、发布脚本。
- 要改 `AGENTS.md` 的结构（不是加一行内容，而是改路由分类）。
- 旧代码看不出意图，且没有测试覆盖。

## 反模式

- ❌ 「顺便把命名统一了」——评审成本翻倍，回滚粒度变粗。
- ❌ 用注释解释错误的代码，而不是改代码。
- ❌ 为了通过测试改断言。
- ❌ 没跑就说"已验证"。
