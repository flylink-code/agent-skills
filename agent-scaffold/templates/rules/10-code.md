# 改代码纪律

## 顺序（不可跳）

1. **定位**：用 `doc/CODE_MAP_INDEX.md` 的 `--find` / `--outline` / `--map` 拿 `路径:行号`，再打开文件。不做全仓盲扫。
2. **读懂**：改动点上下游各读一层（调用方 + 被调用方）。不确定就写「我不确定 X」。
3. **改**：最小 diff。不动无关格式、不顺手重命名。
4. **验**：跑该模块测试或最小可执行路径；跑不了就明说「没跑」，**不写**「应该没问题」。
5. **记**：影响面写进提交信息，重大取舍写进 `agent/context/decisions.md`。

## 最小 diff 的具体含义

- 一个提交只解决一件事。夹带的重构单独提。
- 不引入新依赖、不升级锁定版本，除非用户同意。
- 生成物（`doc/codemap/**`、`doc/CODE_MAP_INDEX.md`）只由生成器写。
- 跨 3 个以上文件时，先说明为什么要跨。

## 多工程隔离

改一个工程时，**不得**顺手改另一个工程的文件、公共配置、共享接口。
需要跨工程改动 → 先读 `agent/rules/70-isolation.md`，说明理由并取得同意。

## 什么时候必须先问

- 删/改公共 API、数据库结构、对外协议、产线参数。
- 动构建配置、CI、发布脚本。
- 改 `AGENTS.md` 的结构（不是加一行内容，而是改路由分类）。
- 旧代码看不出意图且无测试覆盖。

## 反模式

- ❌ 「顺便把命名统一了」——评审成本翻倍，回滚粒度变粗。
- ❌ 用注释解释错误的代码，而不是改代码。
- ❌ 注释 / TODO 里写「按你的要求…」「后续按需求完善」——对话痕迹不进产物，见 `agent/rules/15-audience.md`。
- ❌ 为通过测试改断言。
- ❌ 没跑就说「已验证」。
