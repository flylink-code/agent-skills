# 文档规范

## 先问：这属于哪一类

| 类型 | 放哪 | 谁维护 |
| --- | --- | --- |
| 需求 / 验收 | `docs/` 原位（不动），摘要进 `agent/context/requirements.md` | 人 |
| 硬件：原理图、BOM、接口 | `docs/` 原位，摘要进 `agent/context/hardware.md` | 人 |
| 软件：架构、协议、版本 | `docs/` 原位，摘要进 `agent/context/software.md` | 人 + Agent |
| 决策记录（为什么这么定） | `agent/context/decisions.md` | Agent 追加 |
| 计划与进度 | `agent/context/plan.md` | Agent 追加 |
| Agent 规则 | `agent/rules/*.md` | 人 |
| 代码地图 | `doc/CODE_MAP_INDEX.md`、`doc/codemap/**` | **只由 code-map 生成器写** |

## 摘要卡规则（`agent/context/*.md`）

固定四段，缺一段就是不合规：

```markdown
## 事实源
- 需求 v2.3：`docs/req/需求_v2.3.docx`（唯一有效版本，旧版已作废）
## 当前结论
- 采样率 600 Mbps；AC 本期不做。
## 未决项
- DQ 收尾失败的兜底策略未定 → 见 `agent/rules/40-debug.md`
## 最后更新
- 2026-11-12 / 更新人
```

- **只写指针与结论，不搬正文**。正文会过期，链接不会。
- 一个事实源只能有一个"有效版本"，其余标注"已作废"。
- 摘要卡超过 200 行说明该拆了。

## 写文档的通用要求

- 先给结论，再给依据；不要让读者读到第三段才知道你要说什么。
- 数字带单位和口径（600 Mbps 是链路速率还是采样率？）。
- 时间用绝对日期（2026-11-12），不用"上周""昨天"。
- 路径用仓库相对路径，不写本机绝对路径（`D:\...`、`C:\Users\...`）。
- 术语首次出现给英文原词。

## 反模式

- ❌ 新建 `xxx_最终版_v2_真的最终.docx` —— 版本靠 git，不靠文件名。
- ❌ 在仓库里放截图而不放文字结论 —— 图不能 grep。
- ❌ 把会议记录原文当决策记录 —— 决策只要"决定了什么 + 为什么 + 放弃了什么"。
