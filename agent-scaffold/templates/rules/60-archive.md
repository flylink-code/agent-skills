# 归档与状态

归档的目的不是「存起来」，而是**让后来的 Agent 不再重复做已完成的事，也不会把旧结论当现状**。

## 状态模型

| status | 含义 | Agent 可否当现状用 |
| --- | --- | --- |
| `active` | 当前有效 | 可以 |
| `resolved` | 已解决，结论仍有效 | 可以，但先看复验条件 |
| `superseded` | 被新方案取代 | **不可以**，改读 `superseded_by` |
| `archived` | 已归档 | **不可以**，只作历史背景 |

## 什么时候归档

- 缺陷已修复**且有复现用例验证通过**
- 需求已交付并验收
- 阶段收敛（调试告一段落）、要换人或交接
- 方案被取代

**不能归档的情况**：根因未定只做了绕过 → 标 `workaround` + 复验条件，留在活跃区。

## 归档五步（缺一步不算归档）

1. **定稿结论**：最终结论 + 证据等级 + 复验条件 + 当时 commit 号。
2. **改状态**：frontmatter 写 `status: archived`、`archived: 日期`、`superseded_by`。
3. **移入归档区**：`agent/context/archive/<主题>.md`，原文保留，追加「不要重做」段。
4. **登索引**：`ARCHIVE_INDEX.md` 加一行（主题 / 结论一句话 / 状态 / 失效条件）。
5. **清活跃区**：从 `plan.md` 删已完成项、从 `index.md` 移除失效触发、从 `AGENTS.md` 移除已固化条目。

## 归档卡结构

```markdown
---
status: archived
archived: 2026-11-12
commit: abc1234
superseded_by: null
valid_until: 2026-11-12
---

## 结论（最终）
- 实测：DQ 收尾超时的根因是 X；修复见 commit。
## 证据
- 复现用例：`tests/dq_finish.test`；修复前后各 50 次结果。
## 不要再做（重要）
- 不要再重复「换线束」实验（2026-11-10 已做 10 次，排除）
- 不要再用 1.0 固件验证（已废弃）
## 失效条件
- 换板号 / 换固件大版本 / 采样率 > 800 Mbps → 结论作废，需重新验证
## 原始记录
- 归档前所在：`agent/context/archive/2026-11/dq-finish.md`
```

## 引用前的强制检查

任何结论在被当作「现状」之前：

1. 看 `status`；非 `active` / `resolved` → 不得作为现状。
2. 看 `valid_until` 与环境条件；环境变了 = 失效。
3. 看 `superseded_by`；有取代项 → 读取代项。

## 防重做

会话开始、以及接手「看起来做过」的任务时：

- 先搜 `ARCHIVE_INDEX.md` 的主题词与 `archive/` 文件名
- 命中 → 先读结论与「不要再做」清单，再决定是否真的需要重做
- 若确实要重做（环境变了）→ 在归档卡上追加「2026-11-12 重新开启，原因：X」，不要直接删历史

## 反模式

- ❌ 归档时删掉原文件 —— 只移动，不销毁。
- ❌ 归档卡只写「已完成」—— 后来者不知道完成到什么程度、哪些路走不通。
- ❌ 把 `archived` 的结论当活跃结论引用（最危险）。
- ❌ 归档后不更新 `plan.md`，导致下次又被排进待办。
