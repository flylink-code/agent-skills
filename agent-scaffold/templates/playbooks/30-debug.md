# 阶段三：调试 / 定位

目标：把「有现象」变成「有根因 + 有验证」，而不是「试了一下好像好了」。

## 步骤

```
Task Progress:
- [ ] Step 1: 固定现象（可复现 + 环境记录）
- [ ] Step 2: 查历史（归档 / 决策 / 已有 issue）
- [ ] Step 3: 列假设并排序
- [ ] Step 4: 设计证伪实验（一次一个变量）
- [ ] Step 5: 执行、记录、更新假设
- [ ] Step 6: 收敛到根因或明确的分叉点
- [ ] Step 7: 修复 + 回归 + 决定是否归档
```

### Step 1: 固定现象

必须记录：现象描述、触发条件、复现率（N 次中 M 次）、环境（板号/固件/温度/电压/上电顺序）、首次出现时间。

**复现不了也要记录**：说明尝试过的条件组合，这是后续排查的边界。

### Step 2: 查历史

- `agent/context/archive/ARCHIVE_INDEX.md` 搜关键词
- `agent/context/decisions.md`
- 代码里的 `TODO` / `FIXME` / 相关提交

**这一步能省掉一半重复实验。** 命中归档项 → 先读「不要再做」清单。

### Step 3: 假设

每条假设写：内容 + 置信度 + 若成立会看到什么 + 若证伪会看到什么。
按「信息增益 / 成本」排序，先做便宜且能一刀切开的实验。

### Step 4: 证伪实验

固定输出四段：

```markdown
### 1. 当前证据（只列实测）
- 实测：DQ 收尾阶段返回 X，时间戳 T1（来源：日志行号）

### 2. 假设（按可能性排序）
- H1 [高] 状态机缺少超时兜底 → 证伪：注入 5s 延迟
- H2 [中] 上电时序导致首帧异常 → 证伪：冷启动 3 次取首帧
- H3 [低] 连接器接触不良 → 证伪：换线束重复 10 次

### 3. 下一步（≥3 条，带判定标准）
- 做 X → 看 Y → 若 A 则 H1 成立；若 B 则排除 H1

### 4. 未决 / 需要什么
- 需要：DQ 收尾阶段完整日志（从首个异常到 SAFE 触发）
```

### Step 5: 执行与更新

每轮结束更新假设表：确认 / 排除 / 降级。**不要**保留已被证伪的假设继续占用注意力。

### Step 6: 收敛

两种情况都算收敛：

- 找到根因 → 进入修复
- 切不开 → 明确写出「区分 A 与 B 需要观测 X，获取方式 Y」，并给用户可执行的取数步骤

**不允许**以「证据不足，无法确定」结束一轮。哪怕本轮只是排除了两条假设，也要写清排除了什么、依据是什么。

### Step 7: 修复与归档

- 修复必须有复现用例，修完用例通过
- 只绕过未修根因 → 标 `workaround` + 复验条件，**不归档**
- 真修复 → 按 `agent/playbooks/50-archive.md` 归档，把「不要再做」写清楚

## 完成判据

- 现象可复现（或已说明不可复现的边界）
- 根因有直接证据，或分叉点有明确的下一步观测
- 修复有回归证据
- 归档卡能让下一个 Agent 不再重做

## 反模式

- ❌ 一次改多个变量。
- ❌ 把「换了就好了」当根因。
- ❌ 结论不带环境信息。
- ❌ 把「按用户要求加的打印 / 临时开关」留在注释、TODO 或日志里——调试痕迹可以留，对话痕迹不行（`agent/rules/15-audience.md`）。
- ❌ 修完不写归档，下次重头再来。
